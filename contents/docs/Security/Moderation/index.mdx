# Moderation

Guide to setting up moderation commands in your server.

## Overview

<Note type="warning">
  The role hierarchy of the bot is very important. Place gato role on top of all
  managable roles.
</Note>

The moderation commands need a setup before being used. Follow the steps below
to set them up properly.

<Stepper>
  <StepperItem title="Jail Configuration">
    To configure the jail feature and ensure the role and channel are created correctly, run the setup command:

    ```plaintext
    ,setup
    ```

    This will automatically create a "jail" role and a dedicated channel with the correct permissions.
    The default duration is set to 4 weeks.

  </StepperItem>

  <StepperItem title="Mute Configuration">
    To configure the mute feature and ensure the role and channel are created correctly, run the setup command:

    ```plaintext
    ,setmute
    ```

    This will automatically create a "mute", "rmute" and "imute" roles.
    The default duration is set to 1 hour.

  </StepperItem>
</Stepper>

Once created, the following roles meaning are :

- `jail` : a member with this role will be jailed for a specific duration
- `mute` : a member with this role will be muted for a specific duration
- `rmute` : a member with this role will be unable to react to messages for a specific duration
- `imute` : a member with this role will be unable to attach files in messages for a specific duration

All commands follow the same syntax and options :

    <Tabs defaultValue="syntax" className="pt-3 pb-0.7">
        <TabsList>
        <TabsTrigger value="syntax">Syntaxe</TabsTrigger>
        <TabsTrigger value="example">Exemple</TabsTrigger>
        </TabsList>
        <TabsContent value="syntax">
        ```plaintext
        ,jail (user) [duration] [reason]
        ```
        </TabsContent>
        <TabsContent value="example">
        ```plaintext
        ,jail @john 2h spam
        ```
        </TabsContent>
    </Tabs>

## Staff Roles

It’s important to set the staff roles in your server to ensure that gato can
identify who has dangerous permissions. This is necessary for the stripstaff
punishment to work.
Use the `,settings staff @role` command to set a role as a staff role, you would
re-run the command if you don’t want a role set as staff anymore.

    <Tabs defaultValue="syntax" className="pt-3 pb-0.7">
        <TabsList>
        <TabsTrigger value="syntax">Syntaxe</TabsTrigger>
        <TabsTrigger value="example">Exemple</TabsTrigger>
        </TabsList>
        <TabsContent value="syntax">
        ```plaintext
        ,settings staff (role)
        ```
        </TabsContent>
        <TabsContent value="example">
        ```plaintext
        ,settings staff @Modo
        ```
        </TabsContent>
    </Tabs>

## Invoke Messages

Each commands is customisable in terms of the message that gets sent, in private message or in the server.
The follwing commands : `jail`, `kick`, `ban`, `tempban`, `softban`, `hardban`, `timeout` & `warn` are customisable.

<Note type="note">
  The message can be raw text or embed, learn more about it
  [here](/ressources/script/embeds) and about placeholders
  [here](/ressources/script/placeholders)
</Note>

    <Tabs defaultValue="syntax" className="pt-3 pb-0.7">
        <TabsList>
        <TabsTrigger value="syntax">Syntaxe</TabsTrigger>
        <TabsTrigger value="example">Exemple</TabsTrigger>
        </TabsList>
        <TabsContent value="syntax">
        ```plaintext
        ,invoke (command) (message or dm) (message)
        ```
        </TabsContent>
        <TabsContent value="example">
        ```plaintext
        ,invoke jail message {user.mention} has been jailed for {reason}
        ,invoke jail dm {user.mention}, you have been jailed for {reason}
        ```
        </TabsContent>
    </Tabs>
